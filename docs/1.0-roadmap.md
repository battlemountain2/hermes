## 1. Unified search foundation — proposed first milestone

First query-contract increment implemented October 14: exact quoted artist/album/title filters
compose with existing filters, dialog and result tabs reject stale query generations, and tabs
preserve relevance order until explicitly sorted. Separate coverage notices remain visible with
matching results and survive view changes. The filter popover scrolls on short screens. This is
not the durable catalog or grouped entity migration: current index/result limits remain.
See `search-storage-evaluation.md` for the generated SQLite prototype and remaining storage gates.

Persistent catalog increment implemented October 14: general searches use shared monitored
catalogs with private SQLite snapshots and source revalidation on restart. Home delegates its Music
subtree to the existing song catalog; complete active parent catalogs serve narrower folder searches.
Cold names publish while metadata arrives, and additions/removals/renames update open searches.
This increment retained the existing fuzzy scorer and40k/32MiB/100-result limits. SQLite stores
snapshots here; Smart Folders remain next after the pagination/grouping increments below.

Indexed-filter/pagination increment: the dialog starts with100 ranked matches and More extends
that same query snapshot by100. Result tabs request all matches in the bounded index. Generation,
revision and shown-count tokens reject obsolete or duplicate page requests; catalog changes reset
the dialog to a new first page. Counts and the More control occupy fixed slots, retaining row identity
and selection during paging. Exact type/extension/artist/album/title constraints use a lazy in-memory
SQLite candidate index after the catalog settles. Every eligible candidate is scored and ranked;
there is no arbitrary candidate cutoff. Plain fuzzy queries still exhaustively score the bounded
catalog, and unsupported/failed candidate indexing falls back to that same scorer. This is not FTS5
or an increase in catalog coverage.

Grouped-search increment: primary All/Files/Songs/Albums/Artists navigation is separate from type
filters. All distributes page prefixes across nonempty groups and displays section headers. Albums
key on album artist (fallback track artist) and album title; artists key on track artist (fallback
album artist), case-insensitively. Compilation/disc folders can therefore join without conflating
same-title albums by different artists. Entity labels must match free terms, not merely a song title.
Counts describe eligible matching song files, not an exhaustive discography. Untagged audio remains
in Songs; missing names are not guessed from folder names. No virtual filesystem paths are created.

Opening an entity drills into its matching songs in the same search, preserving query/scope/filters.
Album drilling and its exported song tab follow disc/track tags, with filename-number fallback;
artist drilling and ordinary search retain relevance ordering.
Back restores the previous group/selection; editing filters/query, Refresh or changing scope clears
drilling. Representative artwork uses the existing visible-only thumbnail path. Stable typed keys
separate a real file from entities that share its artwork path. A16MiB/40k derived-entity budget
reports partial grouping while retaining all physical matches in the bounded source catalog.

Search tabs remain physical Files/Songs, not virtual album/artist folders. Export is disabled while
browsing Albums/Artists until an entity is opened. Scoped URLs now preserve Files/Songs and normalized
entity membership separately from the free query, retaining legacy URL compatibility. Compilation
membership uses album artist without replacing explicit track-artist filters. Grouped payloads are
rejected by the physical file adapter. Broader fuzzy acceleration remains a separate release gate.

Saved-search increment: Save search keeps the current query, scope, physical result group and any
drilled album/artist membership as a named Smart Folder. Sidebar links open current matches through
the same live search adapter without copying files or indexing again. A separate manager edits names,
queries and locations, preserves stale editor fields, and confirms removal of saved definitions.
Definitions use bounded private authoritative storage, distinct from rebuildable catalogs. Invalid or
externally changed storage is preserved; reload is explicit. See `saved-searches.md` for controls,
limits, persistence and UI-state behavior. Index coverage has not increased.

Built-in smart-search guardrails (October 15): Smart Folders and Save search are hidden by default,
without deleting saved definitions. Hidden sidebar updates acknowledge store revisions without
recreating rows. Natural-language interpretations retain direct filename/tag alternatives and rank
those ahead of inferred matches, while explicit filters stay strict. SQLite candidates cannot prune
literal alternatives, and label grouping only uses interpretations applicable to each matching song.
Quoted terms remain literal through matching, grouping and filter Apply/Clear. Inferred-chip dismissal
uses original token spans, preserving Unicode, repeated words, escapes and interleaved typed filters.
Calendar/date semantics, selected roots, content opt-in and catalog limits are unchanged.

Search-layout increment (October 16): inferred chips and status notices share a permanently
reserved compact line rather than separate rows appearing/disappearing. Idle/loading/count text
changes in place; long chips live in a bounded-width, keyboard-scrollable viewport with full
tooltips, and long scope paths no longer increase preferred panel width. The original connected
GTK geometry regression and a10/13/22px font matrix cover panel, status, results and footer bounds.
This removes update-driven resizing without freezing the selected interface font or adding resize
timers. It is not an end-to-end frame-rate or search-latency benchmark.

### Current constraints verified in source

- General searches now share monitored root catalogs with durable SQLite snapshots; Music retains
  its existing persistent monitored catalog. Home delegates Music to that catalog instead of
  reading the same song tags through a separate Home scanner. Additional scope roots still have
  separate snapshots; complete active parent catalogs can serve contained folder searches.
- General indexing caps at 40,000 entries/32 MiB and metadata at 20,000 reads. Dialog results are
  paged in100-match increments; result tabs expose all matches within that index. Warnings exist,
  but large Homes can still be incomplete. Paging does not remove the catalog coverage limit.
- Hidden paths are skipped; other exclusions and a user-facing indexing policy are needed.
- Existing filters include type, extension, path substring, recent modification, content and
  exact artist/album/title fields; sizes, compound rules and saved searches are not complete.

### Proposed architecture

One local catalog/query service used by global search, Music search and result tabs. Cheap
filename/path/type/date/size data arrives first; bounded background metadata enriches the same
records. Reuse music identities/tags instead of adding a third tag scanner. Folder filtering
remains a separate fast operation over the current listing, with clearly different labeling.

Evaluate SQLite plus FTS5 as the default storage candidate using a generated benchmark before
committing to a new dependency. FTS5 supports token/prefix/full-text queries; typo tolerance and
filename substring behavior need explicit bounded candidate retrieval/reranking, not an assumption
that FTS5 provides arbitrary fuzzy matching. Retain current identity/cancellation/sandbox safeguards.

Catalog invariants:

- Durable local index, bounded write batches and low-priority scan/metadata workers off GTK.
- Query generations prevent late responses replacing newer text; bounded, paginated results.
- Stable field-aware ranking: exact title/name before prefix, token, substring and fuzzy matches.
- Unicode/accent handling and quoted names, including punctuation-heavy song titles, are tested.
- Watcher updates, periodic reconciliation, overflow recovery and restart freshness checks.
- Exclusions, pause/rebuild/clear controls and clear initial/partial/stale/offline coverage states.
- Home default, optional additional local roots, no network/removable-drive crawl without consent.
- No symlink recursion; inaccessible folders reported, not treated as an empty successful scan.
- Schema migrations/rebuild recovery never touch original files or silently discard collections.
- Explicit budgets for index storage, RAM, scanning and metadata; report incomplete coverage rather
  than merely raising the old entry limit. Query latency and scan completeness are separate goals.

### Unified search experience

One entry point with All, Files, Songs, Albums and Artists views, plus file-type chips such as
Images, Videos, Documents, Applications and Archives. Albums/artists are virtual catalog entities,
not ordinary folders renamed in the UI. Do not duplicate the same song in All as both a generic
file and a song. Artist identity/grouping must handle compilations and album artists deliberately.

Keep type badges and lazy artwork, show concise paths/artist/album, highlight the matching field,
and preserve selection while metadata enriches results. Keep exact matches above fuzzy guesses.
Expose Open, Preview, Reveal, Copy location and applicable queue actions consistently. Persist
search scope and filters into result tabs so the same query does not behave differently there.

Friendly filters and optional equivalent typed queries: `artist:`, `album:`, `title:`, `type:`,
`ext:`, `in:`, date, size and explicit `content:`. These are proposals, not all existing syntax.
Saved searches now reuse this query model. Examples supported by existing filters include recent
videos, a specific artist's FLAC songs, or images in a chosen folder. A compound-rule builder,
ratings and size-filter support remain separate work.

Content stays opt-in: reuse bounded sandbox text extraction, with type/size/time limits and visible
partial results. No full-drive PDF parsing, OCR, cloud search or semantic/AI index for the first pass.

## 3. Everyday file-manager confidence

Pre-1.0 priorities after search/media:

1. Operation audit: clipboard interoperability, large and partial transfers, cancel behavior,
   duplicate-name choices, folder merge safety, permission failures and disk-full handling. Keep
   safe staging; define which operations are undoable. Existing undo is not a promise of redo or
   universal rollback. Improve visible progress/jobs feedback without inventing completion.
2. Music collection continuity (Implemented October 17, 2026): updates favorites, playlists,
   and listening history for moves and renames initiated by Hermes across single files and directories;
   preserves unavailable entries and offers repair via native file chooser.
3. Per-folder view preferences: images use grid, documents use details, albums use metadata track
   order; user choices override heuristics. Existing saved tab preferences are not per-folder rules.
4. Preview usability: document find/select/copy where supported, readable missing-type states,
   keyboard focus, narrow/high-scale panes, theme consistency and reduced-motion behavior.
5. Optional larger-file metadata: useful photo dimensions/camera and video codec/duration details
   through bounded existing providers; do not block first display on a technical-property scan.
6. Ratings (Implemented October 17, 2026): local 5-star ratings for photos, videos and documents,
   strictly excluding music (favorites/hearts remain distinct). Stored atomically in Hermes without
   modifying files or audio tags. Follows moves and renames via continuity. Interactive in Preview drawer,
   browser item context menu, and search queries (`rating:5`, `rating:>=4`, `rating:unrated`).

Audit existing GIO/device behavior rather than marking all remote browsing or removable storage
missing. Remote auth/reconnect/host-key handling, phone backends and remote previews remain
backend-dependent/unverified and require explicit test fixtures and scope decisions.

## 4. Performance and release gate

- Shared album art plus separate small raster tiers for model/comic thumbnails.
- Profile first photo/video selection separately from thumbnail feedback and warm revisits.
- Measure index queries, new folder display, retained-tab switching, scrolling and active playback
  concurrently. Record p50/p95, memory and main-thread stalls, not only one best sample.
- Suggested acceptance target: warm indexed first-page queries under100ms p95 on a documented
  representative local corpus. This is a target, not a current claim or all-drive guarantee.
- Test generated10k/100k-file collections, non-ASCII names, duplicate albums, root overlaps, restart,
  concurrent changes, unmounts, corrupt caches and incomplete scans. Agree disk/RAM budgets first.
- Verify real Wayland fractional scaling, theme switches, keyboard-only use and selected physical
  media cases; headless checks do not establish compositor parity or subjective smoothness.
- Resolve or explicitly triage known broad-suite failures, rather than relying only on the600
  passing binary unit tests. Preserve sandbox safety and the user's settings/collections.
- Packaging/dependency/error diagnostics, desktop Open file location behavior, clean startup and
  restart recovery need a fresh-install smoke test before release.

1.0 should mean dependable daily file/media workflows, not the entire feature union of three mature
file managers. Do not promise Dolphin-equivalent speed until a controlled same-folder comparison.

## Parallel agent work plan

The user approved splitting work across agents on October 13. An initial read-only agent pass
maps ownership and dependencies; implementation remains staged. Use two or three implementation
agents at a time, with one integration owner. Do not assign the entire roadmap simultaneously.

First establish the shared search contract: canonical scope/query/filters and explicit content
consent, stable result identities, request generations, snapshot-aware pagination, relevance order,
and structured coverage notices. Preserve legacy search URIs. Album/artist entities must not use
invented filesystem paths. Benchmark the storage candidate before adding a production dependency.

| Assignment | Exclusive implementation scope | Dependency and completion gate |
| --- | --- | --- |
| Catalog and queries | `src/services/search.rs`, `src/services/search/`, `src/services/music_library.rs`, `src/services/music_library/`; new catalog modules as agreed | Reuse music metadata; generated restart, cancellation, freshness and bounded-query checks; storage benchmark first |
| Search interface | `src/ui/search.rs`, `src/ui/search/`, `src/adapters/search_source.rs`, adjacent adapter tests | Consume the agreed contract; synthetic responses allow parallel UI work; verify selection, late-response rejection, pagination and coverage notices |
| Integration owner | `src/services/mod.rs`, navigation/window wiring, shared model/settings/style files, dependency manifest and lockfile | Review each patch and combined behavior; own shared-file edits so agents do not collide |

Two integration issues need explicit coverage: result tabs currently pass through ordinary file
sorting, which can lose relevance order, and their adapter discards coverage notices when matches
exist. Fix these alongside the service/UI migration, rather than declaring dialog parity sufficient.

Smart Folders follow the stable query contract and persist named queries as authoritative user
data, separately from the rebuildable index. Grouped Albums/Artists need deliberate activation and
navigation behavior; the first migration can preserve existing file/song behavior before adding
virtual entities. Later waves cover music presentation, collection continuity/ratings, then the
operation and document audits. Each wave must preserve completed features and include focused
checks plus a combined build before the next shared-interface change.

Later assignments can run in pairs with these boundaries:

- Music presentation owns audio-preview layout and the played-PCM spectrum path in playback/stream
  modules. Shared artwork owns music-metadata discovery and thumbnail scheduling/cache modules.
  Keep their current artwork API stable until integration; preserve independent track validation.
- Collection continuity owns operation events, local operation completion mappings and collection
  persistence. Agree successful old-to-new mappings first: current rename events only identify the
  request, and completed transfers omit the destination. Copies must not relocate source metadata;
  partial failures, directory descendants and destination collisions need explicit handling.
- Ratings owns new dedicated service/UI modules and consumes that relocation contract. Enforce
  photo/video/document eligibility in the storage API as well as the UI. Search reads ratings via
  an interface; rebuilding the search index must never erase them.

Preview/browser/window integration, shared styles/settings, module registration and icon resources
stay with the integration owner in every wave. Preserve the substantial existing working-tree
changes; review against a recorded starting state and never revert another lane's work. Use generated
fixtures for testing, with no user-app restarts or personal collection rewrites for validation.
